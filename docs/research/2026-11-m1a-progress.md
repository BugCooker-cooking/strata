# M1a 实施记录

日期：2026-11-03。状态：功能闭环和当前 Mac 验收通过，正在完成提交后的干净构建和远程 CI 验收。

[详细计划](../plans/2026-11-02-m1a-core-storage.md)的边界是像素图层编辑、命令与历史、工程往返和 PNG/TIFF 双位深导出。它不是完整 M1 或可公开发布的成品。仓库保持私有；当前 Mac 先行验证，M0 缺少的 macOS 14、M1 标准机、跨屏、真实触控板和校准对色仍见[实机表](2026-11-m0-hardware-checklist.md)。

## 功能与正确性

- 256×256 RGBA8/RGBA16 稀疏 COW 块；稳定块版本、负坐标、透明非零 RGB、相邻 16 位样本均有回归测试。
- 单画板、稳定文档/图层 ID、排序、名称、显隐、不透明度、位置、Normal/Multiply/Screen/Overlay；显式 sRGB/Display P3 工作空间转换。
- 25 个注册命令，参数和结果 schema 从类型生成；AppKit、FFI、开发工具共用执行器。来源和资源由宿主绑定，不能用 JSON 任意路径或自报 AI/User 绕过权限。
- 原子批事务、先前结果 ID 引用、revision/控制 epoch、并发重复 call ID 去重；停止和迟到候选不会提交；事件锁外发送。
- 线性撤销/重做、来源标记、尾部回合分组。拖动使用独立预览，松手一条历史，取消不改文档；保存/导出执行记录不随撤销恢复。
- SQLite `.strata` v0 保存稳定 ID、图层属性、ICC 和原位深块；首次/另存同目录临时文件验证后原子发布，普通保存增量事务。固定快照防止晚到保存清除新编辑的脏状态。
- PNG/TIFF 8/16 位精确往返。修复小 TIFF 的 ICC 被上游解码限制静默丢弃问题，使用同一文件句柄的有界 profile 读取。

实现和格式细节见[工程格式与命令契约](2026-11-m1a-format-and-commands.md)。多层混合目前在 CPU 上以 f64 分块计算，GPU 负责线性 P3 纹理、缩略采样和屏幕显示。独立解析参考验证四种模式的 alpha/opacity 和两个 Overlay 分支，编辑导出容差为 8 位 1 码值、16 位 3 码值；GPU 8 位表面读回容差为 2 码值。显示缓存从不成为保存源。

## 当前 Mac 原生验收

Apple M4 / 16 GiB / macOS 27.0.1，Xcode 27.1。本机强制 Metal；远程无 GPU 时的跳过不替代本机验证。

1. 冷启动后窗口置前即显示样片与画板边框/名称，无需点击 Fit。后台启动时系统暂停被遮挡窗口的 display link，窗口可见后会呈现待处理帧；已移除调试用同步渲染和 HUD 字段。
2. 原生打开先前工程，修改图层名称、55% 不透明度、滤色、顺序并拖动；拖动只增加一条历史，撤销/重做位置一致。
3. 另存 `build/m1a-ui-final-20261103.strata`，重开后恢复顺序、属性、位置与活动图层，状态干净。SQLite `integrity_check` 返回 `ok`。
4. 原生导出同名 PNG/TIFF，格式切换自动更正扩展名。`strata-devtool verify-exports` 比较重开工程与两张输出的尺寸、全部样本和 ICC，结果完全一致；证据见 `data/2026-11-03-m1a-native-exports.json`。
5. 显隐修改后关闭出现保存/取消/不保存；取消保留文档，撤销至保存状态恢复干净标记，正常退出。工程 UTI 声明避免另存面板重复追加后缀；Release 原生面板复核默认名称为 `sample-photo.strata`，XCTest 同时覆盖该类型关联。

Esc 在连续拖动中的物理按键验收尚未用真实触控板执行；核心取消/过期会话与 FFI 路径有自动测试，物理手感继续留在 M0 实机表。

## 自动化与文件安全证据

本机 `make lint`、`STRATA_REQUIRE_GPU=1 make test`、`make commands` 和 Release 构建通过：103 项 Rust 测试（含 11 项 GPU 集成测试）、10 项 XCTest、25 个命令隔离示例。最终提交的干净构建和远程 CI 记录在收尾后更新。

`strata-devtool demo` 覆盖 PNG/TIFF×8/16 位四种输入，通过复制、改名、位置/不透明度/混合/显隐、undo/redo、保存重开和两种格式导出，精确比较元数据/ID/ICC/样本。证据：`data/2026-11-03-m1a-demo.json`。

文件测试包括坏摘要/未知版本/坏引用/恶意尺寸拒绝，事务前错误、发布前 WriteZero/PermissionDenied/StorageFull、临时工程实际损坏校验、提交前后子进程强制退出，以及发布后同步失败的不确定性区分。热 journal 在私有副本恢复，不修改原件。边界故障注入不等同 SQLite VFS 逐字节短写或真实断电测试。

## 容量与性能

源块上限 512 MiB、128 图层；历史最多 64 条、独立历史块上限 768 MiB；GPU 缓存 1024 块，CPU 合成缓存 128 块。这些是局部限额，不是整个进程的统一内存预算。

`capacity` 使用独立 6000×4000 填色层，目标 20 层：8 位接纳 5 层、503,316,480 字节，创建第 6 层在分配前拒绝；16 位接纳 2 层、402,653,184 字节，创建第 3 层拒绝。接纳创建约 16–34 ms，拒绝小于 0.03 ms。证据：`data/2026-11-03-m1a-capacity.json`。这证明容量防护，不证明 20 层完整驻留通过。

首次 24MP 原生轨迹测得 49.43/53.36/53.36 fps、p95 约 22.3 ms，第一轮有 1.88 s 冷缓存卡顿，未通过，原始失败报告保留为 `data/2026-11-03-m1a-render-before.json`。随后把逐块每帧 uniform 更新合并为共享 camera，预备相邻 mip，并按屏幕刷新率选择不低于 60 的回调档位（160 Hz 屏请求 80，60/120 Hz 屏仍请求 60），仍使用原来的 ≥58 fps、p95≤20 ms 门槛。窗口遮挡/编辑打断的运行作废，不纳入通过证据。

最终 Release 运行 `make benchmark`：4000×6000、8 位、1964×1444 视口、2× backing scale，每轮预热 2 秒、测量 30 秒，共 3 轮。三轮均通过原门槛：

| 轮次 | fps | 帧间隔 p95 | 最大帧间隔 | CPU p95 | 跳过帧 |
|---|---:|---:|---:|---:|---:|
| 1 | 60.00 | 17.82 ms | 32.11 ms | 2.26 ms | 0 |
| 2 | 60.03 | 17.72 ms | 33.34 ms | 2.11 ms | 0 |
| 3 | 60.02 | 17.70 ms | 34.33 ms | 2.26 ms | 0 |

打开耗时 2326 ms，进程峰值 RSS 466,386,944 字节，渲染后采样的最大 physical footprint 713,426,288 字节。完整逐帧数据见 `data/2026-11-03-m1a-render-after.json`。这次系统报告 G27M7Pro 为 120 Hz、请求 60 fps；首次失败报告为 160 Hz，测试没有修改系统刷新率，因此不能把两组数据当作同条件 A/B 或将差值全部归因于代码。160 Hz 回调档位选择由单元测试覆盖，尚未取得该档位的最终实测通过记录。

帧统计为成功 CPU 提交间隔，不是 GPU 完成或屏幕呈现时间；本机结果不替代 M1 标准机和物理手势验收。采样运行标记旧 HEAD 加 `dirty`，对应本次待提交实现；提交后的源代码构建验证另行记录。
