# M0 色彩与位深验证（数值与当前屏幕对色通过）

## 目标与方法

Little CMS 2（lcms2 6.2.0，静态构建其 MIT 库）；测试 8/16 位 ICC→Display P3，不覆盖源文档。P3 profile 使用 D65、P3 原色、sRGB 分段传输函数。

## 结果

- sRGB 红色转换到 P3 约 `[234,51,35]`，8 位误差 ≤1；黑白及 alpha 保留。
- P3 自转换完整 65536 级灰阶逐样本一致；相邻 32768/32769 可区分，16 位 PNG/TIFF 解码精度不丢失。
- 512 组 RGB 采样的 16 位转换，相对 lcms 浮点路径量化后每通道误差 ≤2/65535；alpha 精确复制；不替代将来的独立算子黄金图。
- 损坏 ICC 按 sRGB 回退并标记；能解析但非 RGB 的 ICC 明确拒绝，不把 CMYK profile 套到 RGB 像素。
- `make color-fixtures` 已生成原生 P3 红/绿/蓝/白/灰/黑色块、65536 级灰阶和透明红/不透明白边缘；附 `expected.json`。3 个集成测试验证全样本、ICC 与重复生成的字节一致性；生成器和预期值已入库。
- 2026-11-04 用户在当前 P3 屏幕完成原生六色取样：两应用的红/绿/蓝分别为 `[255,0,0]` / `[0,255,0]` / `[0,0,255]`，白 `[255,255,255]`、灰 `[128,128,128]`、黑 `[0,0,0]`；最大通道差 0，满足 ≤2/255。带 P3 ICC 的照片也确认无明显差异。显示条件、比例及用户实测来源见 [记录](data/2026-11-04-m0-p3-screen-comparison.json)。

## 遇到的问题与 M1 结论

ICC 序列化系数有限精度，即使同一配置也可能在 PCS 往返中损失相邻值。完全相同的配置不重复转换；不通过名称猜测 profile 相同。屏幕浮点缓存与源文档分离，16 位导出不能从屏幕回读。macOS HEIC 与工作空间编辑已在 M1b 实现；灰度/CMYK ICC 仍按格式边界明确处理。当前屏幕对色通过不等于标准机、跨屏、最低系统或显示器校准通过。
