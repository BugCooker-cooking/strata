# 完整 Photoshop 功能覆盖执行范围

2026-11-05。发起人要求“继续推进，直到所有 PS 功能都实现”。当前目标由 v1 剩余 P0 扩展至 [Photoshop 功能全景清单](../research/photoshop-feature-inventory.md) 的完整覆盖；原清单 P0–P3 是实施顺序，不再作为本任务的终止范围。

## 执行原则

- 用户于 2026-11-05 最新明确要求仅本机验证：停止所有云端构建，GitHub 工作流已禁用且移除自动触发。后续不触发/重跑 CI、不等待额度恢复、不要求付费；远程 CI 不再作为开发或闭环门槛。新增云端执行必须重新获得用户明确授权。
- 当前 M3 开发继续完成，不推倒已有 M0–M2 架构；全部能力仍走命令注册表、权限、历史、工程、手工 UI 和 AI 接口。
- 先完成已有依赖链：图层 → 选区 → 调色 → 绘画/修复/滤镜 → 变换/文字/视图 → 产品化；随后扩展 PSD、智能对象/滤镜、路径/矢量、RAW、通道/印刷/HDR、动作/批处理/插件、模型生成与完整专业滤镜。
- 每个功能单独保留“未实现 / 已实现 / 已验收”的状态；注册了名字、禁用按钮、说明文档或回放夹具不能视作功能完成。多动作合并的一行必须全部交付才能关闭。
- 用户追加最终验收：编辑功能全部完成后，逐项核对所有功能是否有 AI 能通过提示发现并直接调用的真实入口。每个实现同步补齐注册/执行器、严格参数/返回值、中文提示/别名、实际示例和权限/历史验证；最终报告列出缺口，不能从注册数量推定全功能可调用。
- 旧清单的“✗”条目重新逐项核对：已由 Photoshop 移除的历史功能保留事实说明；依赖外部云服务的能力另列服务/账号与等效实现依赖，不静默从完整覆盖中删除。
- 核心持续 Linux 可移植；8/16 位和后续新模式的精度、保存重开、撤销、失败安全和资源预算按对应功能实际验证。正式发布仍需真实模型质量集、外部设备、签名公证与发布授权。
- 原生验收一次只开一个 Strata 实例，结束立即退出；本机编译默认两个并发任务，避免测试占满用户机器。
