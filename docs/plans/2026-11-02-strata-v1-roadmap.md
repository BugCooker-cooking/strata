本计划把第一版拆成一个已完成的第一步和九个里程碑（M0–M8），写明每个里程碑交付什么、怎么才算完成、AI 必须能完成哪些任务。每个里程碑开工前，再写一份细到具体代码任务的实施计划（放在 `docs/plans/` 下）。

**本轮修订**：v1.0 的 P0 范围不缩减；M2 分为接口验证 M2a 和真实修图闭环 M2b，只有两者完成才发布 v0.1。基础选区、蒙版、主体选择和曝光调整提前到 M2b；保存恢复提前到 M1；M3–M7 补全已有框架，不重复实现。未勾选项与性能/模型指标仍待验证；M0 本机证据见[实施进度](../research/2026-11-m0-progress.md)。

## 1. 整体走向

### 1.1 先打通一条竖线，再横向铺功能

第一版最大的风险不是某个滤镜做不出来，而是"一切皆命令、AI 通过统一入口驱动"这套地基没有打牢。所以顺序是：

1. **先搭可验证的地基**：显式 8/16 位像素、命令与副作用分类、分块缓存、失败安全的文件读写、Mac 外壳。
2. **尽早接入 AI，再验证修图价值**：M2a 用少量命令验证发现、调用、权限与停止；M2b 跑通“打开照片 → 选择人物 → 带蒙版提亮 → 用户修正 → 撤销/恢复 → 保存重开/导出”。不等待全部图层与调色功能完成。
3. **再横向铺功能**：以已冻结的像素、蒙版、命令、渲染和保存接口为基础补全 v1；每个功能增加命令、人机界面和评测，不额外建设第二套 AI 编辑路径。

这样做的好处：硬规则在命令只有十几个的时候就被验证；后面每个功能都不需要再单独"接 AI"；问题暴露得早，返工成本低。

### 1.2 里程碑总览

```
第一步 界面风格设计 ✅
   │
   M0 项目地基与技术验证
   │
   M1 核心引擎与安全存储 ─────── 文档、命令、历史、权限、分块/缓存、保存恢复
   │
   M2a AI 接口与聊天面板 ─────── 内部集成验收，不单独算公开预览完成
   │
   M2b 最小局部修图闭环 ──────── ★ 预览版 v0.1：主体选择 + 蒙版 + 曝光 + 安全保存
   │
   M3 图层系统补全 / 共享接口冻结
   │
   ├── M4 选区系统补全
   ├── M5 调色补全                按共享接口与验收依赖有条件并行
   ├── M6 绘画、修图与滤镜
   └── M7 变换、文字、视图与色彩
   │
   M8 产品化与发布 ─────────────── ★ 正式版 v1.0
```

> 规模是相对工作量（小 / 中 / 大 / 特大），不是时间承诺。

**并行约束**：M2b 先交付 selection/mask tile、曝光调整、渲染失效与保存 schema；M3 冻结图层树/样式扩展接口。M4 的选区变换使用独立遮罩变换内核，不等待 M7 的自由变换界面；M6 用 M2b 的矩形选区/主体遮罩即可完成基础验收，不依赖 M4 全部工具；M7 的文字必须在 M3 样式管线上做集成验收。M3 的“蒙版绘制”延后由 M6 交付，不提前宣称完成。每条并行工作流须有接口版本、负责人和集成测试后才开工，不能只凭功能目录拆分。

### 1.3 每个里程碑通用的完成标准

除各里程碑自己的标准外，M1 起适用以下标准（M0 按独立技术验证门槛；AI 任务从 M2a 起适用）：

- [ ] 新增的每个功能都是注册过的命令；界面没有绕过命令直接修改文档的路径（硬规则 R1）
- [ ] 每个新命令都有简介、说明、参数说明和至少 1 个示例；CI 在无界面环境下执行全部示例且通过（R2）
- [ ] 本里程碑的"AI 验收任务"在录制回放测试中全部通过，并用至少一个真实模型手动验证过
- [ ] 新功能有对应的界面，人可以手工完成同样的操作
- [ ] 像素算子有标准图对比测试；核心逻辑有单元测试
- [ ] 核心代码在 Linux CI 上编译通过（R8）
- [ ] 固定 Release 基准记录帧时间、内存峰值、冷/热延迟；同机同数据 p95 退步超过 10% 须解释并解决或明确审批，不以 CI 无 GPU 的跳过代替渲染验收
- [ ] 新增文档结构有保存重开/撤销测试；新增外部副作用有授权、失败与取消测试；新命令的批量资格明确
- [ ] 文档更新：命令参考自动生成；有设计变化时同步更新设计文档

- M1 的保存/恢复故障测试与 16 位精度测试全部通过；重开后结构与像素/渲染结果匹配，原始图片不被覆盖；已知限制与基准报告随 Release 提供
- 发布 **v0.1 预览版**（GitHub Release，可先不签名，在 README 中说明安装方式）
